# Thirdweb Unity runtime

Pinned upstream release: [thirdweb Unity SDK v6.1.3](https://github.com/thirdweb-dev/unity/releases/tag/v6.1.3), published 2026-01-14. The release package `thirdweb-unity-sdk-v6.1.3.unitypackage` has SHA-256 `615fd8246a9eee6000004c9d306dbe387b0c094a600fca58fe252c88d4dccc90`, matching GitHub's release digest. The package's Apache 2.0 license is in `LICENSE`.

This directory contains the unmodified `Runtime/NET` assemblies, `Runtime/Unity/Http` source, their Unity metadata, and `Runtime/link.xml` from that package; text line endings were normalized to LF. The local `Thirdweb.Unity.Http.asmdef` exposes the upstream HTTP transport to `Tagtag.Blockchain`. The app uses `ThirdwebClient` and `ThirdwebRPC` for Sepolia RPC and `ThirdwebContract` for ABI encoding. It does **not** create a Thirdweb in-app wallet, call Thirdweb authentication, or store a Thirdweb session.

`PhoneSeedWallet` creates a BIP-39 phrase from on-device randomness, stores it in iOS Keychain, derives `m/44'/60'/0'/0/0`, and signs binding messages and transfer transactions with the bundled Nethereum signer. The pinned Thirdweb DLL does not contain `PrivateKeyWallet`; the app does not depend on that class. The public Thirdweb client ID is an RPC credential only. See [NFT setup](../../docs/NFT_SETUP.md) for recovery, binding, and live verification.

The Blockchain adapter reads ERC-721 ownership at Sepolia's finalized block. Transfer preflight checks current ownership, recipient, and the wallet's Sepolia test ETH balance before signing a legacy EIP-155 transaction locally and broadcasting it through RPC. Mint gas remains app-sponsored. Persist transfer intent before calling `TransferNft`; on `submission_unknown`, reconcile on-chain instead of automatically resubmitting. `GetTransferStatus` remains read-only after disconnect and requires a canonical finalized receipt to mark a transfer confirmed or failed. Provider exception details and wallet secrets are not exposed by the adapter.
