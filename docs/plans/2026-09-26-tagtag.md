# Build tagtag’s shared AR sticker experience

## Summary

Replace the starter screen with a complete iPhone app: **Home**, **STICK**, and **Explore**, following `DESIGN.md`. Users can publish a sticker at their current location, discover another person’s sticker through AR, unlock its note, and collect a copy.

Use Firebase with open signup through Apple and Google. Collections remain app-based for this release. Build directly from the design direction, then verify on physical iPhones.

## App and visual design

- Paper-white backgrounds, near-black text, hand-drawn accents, die-cut artwork, restrained yellow highlights, readable sans-serif controls and notes, and expressive branding.
- The four existing Taggi poses form the initial preset library. Prepare transparent artwork with a white sticker border for the book, map pins, and AR.
- **Home:** collected count above a swipeable book; exactly five rows and four columns per page, ordered by collection time. Details contain artwork, place, author, teaser, full note, and collection date.
- **STICK:** live AR discovery and placement. Preset selection → surface positioning → pinch/rotate → teaser and full note → publish. Preserve unfinished work across permission, tracking, and upload failures.
- **Explore:** interactive Apple MapKit street map, sticker-shaped pins, count clusters, recenter control, and teaser sheet with **Find in AR**. Selected targets carry into STICK.
- Browsing before sign-in; account required for publishing and collecting. Home profile control opens account settings, authored stickers, blocking, and account deletion.
- Safe areas, keyboard avoidance, accessible labels, readable text scaling, 44-point touch targets, and reduced motion. Paper-white appearance is the first-release theme.

## Implementation

### Unity and AR

- Keep Unity `6000.5.5f1`, product `tagtag`, and bundle `com.kenk.tagtag`. Replace the starter UI with a modular UI Toolkit shell, controllers, shared presentation components, and independent collection/discovery logic.
- Add compatible AR Foundation and ARKit packages. Use tracked surface anchors and serialized ARKit world maps for persistence and cross-iPhone recovery.
- Require fresh location and adequate spatial mapping before publishing. Persist preset, transform, coordinates, teaser, note, and recovery snapshot as one publication.
- Restore the selected map and wait for relocalization. Only a direct tap on the tracked sticker within three metres triggers collection. Proximity and map selection never reveal the note.
- Handle denied camera/location access, inaccurate location, poor tracking, recovery timeout, offline errors, unavailable content, and retry.
- Native MapKit bridge exposes viewport, marker selection, visibility, and layout callbacks. Hide and release map interactions when entering AR.

### Firebase and shared data

- Dedicated tagtag Firebase project in Tokyo: Authentication, Firestore, Cloud Storage, Node.js API on Cloud Run.
- Separate preset artwork, public summaries, protected notes/recovery assets, per-user collections, blocks, and reports. Public summaries never contain full notes.
- Operations: nearby browsing, publication preparation/finalization, recovery access, discovery sessions, collection, withdrawal, reporting, blocking, and account deletion.
- Idempotent publication/collection. Retries do not create duplicate placements or increment collection counts twice. Collection leaves the original available.
- Firebase ID-token verification for writes; restricted Firestore/Storage; short-lived recovery access; server checks for location freshness, distance, ownership, content bounds, and publication status.
- AR tap enforced by client plus a server-issued discovery session. This is a gameplay gate, not cryptographic proof of physical presence.
- Cache collections offline and synchronize on reconnect. Withdrawal prevents new discovery. Account deletion/moderation revoke affected notes at subsequent sync.
- Reporting, immediate per-user blocking, text filtering, publication rate limits, and an administrator-only report interface supporting removal/restoration.
- Aim below US$10/month: min instances zero, low max instances, bounded traffic, abandoned-upload cleanup, budget alerts. This target is not a guaranteed spending cap.

### Build and documentation

- Preserve reproducible Unity/Xcode workflow. Prepare ARKit before exporting, and assert native AR libraries are included.
- Use Apple development team `5Y6QUA9GA6`; provisioning must support authentication capabilities.
- Update product/design docs to describe actual behavior and remove obsolete provenance prose. UI, docs, comments, logs, and commits must be specific to tagtag. Retain third-party license notices.
- Independent commits for app shell, local AR, services, integration, and device checks; push completed work.

## Verification and acceptance

- Unity tests: 0/1/20/21-item pagination, swipe versus tap, deduplication, placement transitions, and proximity alone never unlocking notes.
- Backend tests/emulators: authorization, protected notes, retries, failed uploads, stale location, withdrawal, blocking, reports, deletion, quotas.
- Device checks: both sign-ins, account recovery, permissions, interrupted publishing, offline viewing, and restart persistence.
- Two iPhones: A publishes; B sees teaser, relocalizes, taps, reveals note, and collects one copy; original remains available.
- Recovery after restart and changed lighting; ambiguous/failed recovery must not unlock.
- Capture Home, Explore, placement, and collection on iPhone 15 Pro Max and a smaller layout; inspect large text/reduced motion; batch fixes and one confirmation pass.
- Build, sign, install on Dawg., and verify launch/shared flow. Record account/hardware blockers rather than claiming unperformed checks.

## Assumptions

- iPhone only. No Android, NFT minting, freehand creation, trails, or App Store submission.
- A second ARKit-capable iPhone is required for cross-device acceptance.
- Billing, Apple/Google provider credentials, and operator access are configured during deployment. Credentials are never committed.
- Initial library: four supplied Taggi poses, extensible through the same catalog.
