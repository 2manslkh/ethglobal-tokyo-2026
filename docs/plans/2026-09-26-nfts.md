# Automatic sticker NFTs execution plan

Approved brief: new discoveries automatically mint transferable ERC-721 souvenirs on Ethereum Sepolia (11155111), to a Thirdweb embedded wallet authenticated with the existing Firebase JWT. Existing collections are not backfilled. Notes and discovery permissions remain app-based. Chain failures must not block collecting.

## Locked interfaces

Contract: `TagtagSouvenir` ERC721 + AccessControl; name `tagtag discoveries`, symbol `TAGTAG`. Constructor `(address admin,address minter,string[4] presetUris)`. `mint(address recipient,uint256 tokenId,uint8 preset)` minter-only, preset 0..3, immutable preset metadata URI selected per token. `setMintPaused(bool)` admin-only; transfers unpaused. ERC721 prevents token ID reuse; no burn or upgrade API. No user identifiers on-chain.

Backend HTTP:
- `GET /v1/wallet` -> `{enabled:bool,address:string,chainId:11155111}` (empty address if unbound).
- `POST /v1/wallet/challenge` `{address}` -> `{challengeId,message,expiresAt}`; five-minute single-use challenge tied to authenticated UID, address, Sepolia, domain and purpose.
- `POST /v1/wallet/bind` `{challengeId,signature}` -> same wallet status. Verify EIP-191 ownership and consume transactionally; immutable UID/address binding; no cross-account address reuse.
- `CollectedSticker.nft` optional -> `{status,chainId,contractAddress,tokenId,transactionHash}`. Status `pending`, `confirmed`, `delayed`, `cancelled`; old entries omit NFT. IDs/hash/address strings, chainId integer. Queued/waiting/submitted internal states map to pending; faults to delayed.

Unity wallet boundary in `Tagtag.Blockchain`: `IEmbeddedWallet` with `Task<string> Connect(string firebaseIdToken)`, `Task<string> SignMessage(string message)`, `Task Disconnect()`. `ThirdwebEmbeddedWallet(string clientId)` implements it. Wallet SDK assembly independent from Core/Services. Coordinator supplies JWT, binds via HTTP and guards account-generation races. SDK never logs secrets or exports keys. Public config fields `nftEnabled` and `thirdwebClientId`; default false/empty. AppState exposes wallet address/status.

## Operational defaults

Sepolia only; no mainnet; no user transaction prompts for mint; no marketplace. Dedicated backend signer in Secret Manager; administrator separate. Generic metadata/art IPFS pinning requires service access and yields four configured immutable URIs. Account deletion does not erase NFTs, communicated in app. Thirdweb provider setup, RPC, funded signer, deployed contract, pinned metadata and physical devices are rollout prerequisites. Monitor pending age, delayed jobs and signer balance.

Updated user decision during implementation: add a standard ERC-721 transfer-out flow before deletion. The wallet owner implements Sepolia-only SDK sends, ownership reads and finalized receipt checks; the coordinator owns recipient UI, durable pending/submitting/unknown transaction records, and an explicit acknowledgement before the deletion fallback. Transfer gas is paid from the embedded wallet in Sepolia test ETH; minting remains sponsored. No additional contract transfer privileges or marketplace. This supersedes the earlier no-transfer-out decision. Deleting Firebase sign-in may still strand pending mints or NFTs left behind, so deletion remains available only with informed acknowledgement.
